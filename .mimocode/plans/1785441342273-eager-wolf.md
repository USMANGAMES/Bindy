# Plan: Prototype to MVP Migration for Bindy

## Goal
Transform the current interactive prototype into a production-ready MVP (Minimum Viable Product) hosted at `app.bindy.uz`, focusing on data persistence, user authentication, and performance optimization.

## Critical Issues to Resolve
- **Synthetic Data**: Remove all static mock data from `src/data/` and replace with real database calls.
- **User Persistence**: Implement a real authentication system to link points and reports to specific users.
- **Performance**: Optimize rendering to eliminate lags on older devices (e.g., iPhone XS).
- **Reliability**: Add error handling for AI analysis and network failures.

## Implementation Phases

### Phase 1: Infrastructure & Database (The "Backend Core")
- **User Model**: Create a `users` table in SQLite (`server/store.py`) with fields for `id`, `username`, `email`, `total_points`, and `created_at`.
- **Auth System**: Implement a lightweight authentication mechanism (start with simple JWT or session-based auth) in `server/main.py`.
- **Data Migration**: Update all API endpoints to require a `user_id` and interact solely with `server/store.py` instead of mock data.
- **Verification**: Ensure that reports created by User A are correctly attributed and don't affect User B's stats.

### Phase 2: Frontend Refactoring (The "Clean-up")
- **Remove Synthetic Data**: Delete `src/data/` and update all components to fetch data via services.
- **Auth Integration**: Create a simple login/registration flow and store the auth token in `localStorage` or secure cookies.
- **Global State Update**: Update `AppContext.tsx` to handle the authenticated user state and sync with the backend on load.

### Phase 3: Performance & UX Polish (The "iPhone XS Fix")
- **Rendering Optimization**: 
    - Implement `React.memo` and `useMemo` in heavy components (Map markers, Leaderboard lists).
    - Optimize Leaflet marker rendering (consider using `Canvas` renderer).
- **AI Feedback Loop**:
    - Add a "Processing..." loading state with a spinner/skeleton when sending images to Gemma 4.
    - Implement user-friendly error messages for AI failures (e.g., "Image not clear, please try again").
- **Asset Optimization**: Implement image compression on the frontend before uploading to the server to speed up the reporting flow.

### Phase 4: Deployment & Launch
- **CI/CD Setup**: Configure a pipeline for deploying the FastAPI backend and the Vite frontend.
- **Domain Mapping**: 
    - Setup `bindy.uz` for the Landing Page (TBD).
    - Setup `app.bindy.uz` for the PWA.
- **PWA Finalization**: Verify manifest and service workers for a seamless "Add to Home Screen" experience.

## Critical Files to Modify
- `server/store.py`: Add User table and updated queries.
- `server/main.py`: Add Auth routes and update reporting logic.
- `src/context/AppContext.tsx`: Integrate auth and real-time data sync.
- `src/services/`: Update API calls to include auth tokens.
- `src/components/`: Optimize for performance and add loading states.

## Verification Plan
1. **End-to-End Flow**: Register $\rightarrow$ Take Photo $\rightarrow$ AI Verifies $\rightarrow$ Points Added to Profile $\rightarrow$ Marker Appears on Map.
2. **Persistence Test**: Log out and log back in to ensure points and reports are preserved.
3. **Performance Benchmarking**: Test the reporting flow on an iPhone XS to ensure 60fps animations and no freezes.
4. **Stress Test**: Send multiple invalid images to ensure the AI error handling works without crashing the app.
