# Bindy Public Release Plan

The goal is to transform the private repository into a professional, public-facing portfolio project suitable for an accelerator application, while ensuring no sensitive data is leaked.

## Phase 1: Security Scrub (Critical)
- [ ] **Secret Removal**: Replace hardcoded `GEMMA_API_KEY` and `DEFAULT_ADMINS` with environment variable references in `server/.env` and `server/admin_config.py`.
- [ ] **History Purge**: Use `git filter-repo` or `BFG Repo-Cleaner` to permanently remove all occurrences of `.env` files and the `server/data/` directory from the entire Git history.
- [ ] **URL Sanitization**: Replace internal Tailscale addresses (`*.ts.net`) with generic placeholders (e.g., `api.bindy.app`) in all source files and documentation.
- [ ] **Credential Rotation**: (User Action) Revoke and regenerate the `GEMMA_API_KEY` in the provider panel.

## Phase 2: Professional Packaging
- [ ] **Gitignore Optimization**: Ensure `server/bindy.db`, `server/data/*.json`, and all `.env` variants are strictly excluded.
- [ ] **Template Creation**: Create a `.env.example` file containing all required variable names with descriptive placeholders and no real values.
- [ ] **README Overhaul**: Write a comprehensive `README.md` including:
    - Project Pitch & Value Proposition.
    - Tech Stack (Frontend, Backend, AI Model).
    - High-level Architecture Description.
    - Local Setup & Installation Guide.
    - List of Implemented Features.
    - Future Roadmap.

## Phase 3: Publication
- [ ] **Final Audit**: Run a final grep for any remaining strings like "sk-", "password", or ".ts.net".
- [ ] **Visibility Change**: Set repository visibility to Public.

## Verification
- [ ] Verify that `.env` is not present in the public repository files.
- [ ] Check git history to ensure no previous commits contain secrets.
- [ ] Confirm the project can be understood and potentially run by a third party using the new README and `.env.example`.
